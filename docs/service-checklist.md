# 서비스에 올리기 전 체크리스트

혼자 돌려 보던 봇이나 사이트를 다른 사람에게 공개하기 전에 확인할 것을 모았습니다. 넥슨의 [사전 준비하기](https://openapi.nexon.com/ko/guide/prepare-in-advance/)와 [AI 에이전트 가이드](https://openapi.nexon.com/ko/guide/ai-agent/)에 적힌 의무와 한도를 창작자 입장에서 옮긴 것입니다 (2026-11-24 넥슨 안내 기준). 정확한 조건은 [이용약관](https://openapi.nexon.com/ko/support/terms/)을 확인해 주세요.

## 1. API 키는 서버에만 둡니다

- **키는 서버나 봇(Node.js)에서만 씁니다.** 웹페이지(브라우저)에서 실행되는 코드에 키를 넣으면 방문자 누구나 개발자 도구로 키를 볼 수 있고, 그 키로 내 호출 한도를 다 써 버릴 수 있습니다. 웹사이트는 **웹페이지 → 내 서버 → 넥슨 API** 순서로 거치게 만듭니다 ([FAQ의 서버 예제](faq.md#웹페이지에서-바로-부르고-싶어요)).
- **키를 코드에 직접 적지 않습니다.** `.env` 파일에 두고 `process.env` 로 읽습니다 ([시작 가이드](getting-started.md#3-env-파일로-키-관리하기)).
- **`.env` 를 GitHub에 올리지 않습니다.** `.gitignore` 파일에 `.env` 한 줄을 추가합니다. 키가 노출됐다면 넥슨 Open API의 애플리케이션 상세 페이지에서 새 키를 발급받아 교체합니다.
- **키는 게임마다 따로입니다.** 여러 게임을 다루면 `NEXON_MAPLESTORY_API_KEY`, `NEXON_FC_ONLINE_API_KEY` 처럼 이름을 나눠 저장하고, 게임마다 `NexonClient` 를 따로 만듭니다 ([FAQ](faq.md#api-키가-잘못됐다고-나와요)).

**라이브러리가 하는 일** — 키가 비어 있으면 `new NexonClient()` 에서 바로 알려 줍니다. 다른 게임의 키를 넣었을 때는 어느 게임의 키가 필요한지 에러 메시지로 알려 줍니다. 키를 어디에 두는지는 직접 챙겨야 합니다.

## 2. 서비스 단계 키로 바꿉니다

넥슨의 호출 한도는 애플리케이션 타입에 따라 다릅니다.

| 애플리케이션 타입 | 1초에 | 하루에       |
| ----------------- | ----- | ------------ |
| 개발 단계         | 5건   | 1,000건      |
| 서비스 단계       | 500건 | 20,000,000건 |

- 개발 단계로 만들어 시험하고, 서비스 주소(URL)가 준비되면 **서비스 단계 애플리케이션을 새로 등록**하는 것이 넥슨이 권장하는 순서입니다.
- **서비스 단계로 옮길 때는 API 키를 새로 발급받습니다.** 개발 단계 키가 자동으로 바뀌지 않으므로, 서버의 `.env` 도 새 키로 바꿉니다.
- 한도는 애플리케이션별로 합산됩니다. 게임마다 키가 따로이므로 한도도 게임마다 따로 셉니다.

개발 단계의 하루 1,000건은 생각보다 빨리 찹니다. 이 라이브러리를 실제 서버와 맞춰 볼 때도 개발 단계 키의 하루 한도를 다 썼습니다.

## 3. 호출량을 먼저 셉니다

화면 하나를 그리는 데 넥슨을 몇 번 부르는지 먼저 세어 봅니다. 넥슨이 가이드에 적은 프로필 카드 한 장의 실측입니다.

| 단계                 | 호출 수 |
| -------------------- | ------- |
| 이름 → 고유 번호     | 1       |
| 기본 정보            | 1       |
| 능력치·상세 정보     | 6       |
| **합계**             | **8**   |
| 순위 배지까지 넣으면 | 13~15   |

- 랭킹은 한 번에 한 종류의 순위만 돌려주기 때문에, 순위를 넣으면 호출이 거의 두 배가 됩니다.
- 개발 단계 키는 1초에 5건이라 카드 한 장(8회)도 한꺼번에 부를 수 없습니다. 하루 1,000건으로는 카드 약 125장입니다.
- 길드원 100명을 `Promise.all` 로 동시에 조회하면 1초 한도를 바로 넘습니다. 몇 명씩 나눠 순서대로 조회합니다.
- 한 캐릭터의 순위는 랭킹 페이지를 넘기며 찾지 않습니다. 메이플스토리 랭킹은 `ocid` 를 넣으면 그 캐릭터의 순위만 돌려줍니다 ([메이플스토리 문서](maplestory.md)).

**라이브러리가 하는 일** — 빈 이름이나 잘못된 값처럼 실패할 요청은 넥슨에 보내기 전에 걸러 한도를 쓰지 않습니다. 호출이 너무 잦다는 응답(429)을 받으면 간격을 벌려 자동으로 다시 시도합니다. 화면에 몇 번의 조회를 쓸지와 동시에 몇 건을 보낼지는 직접 정해야 합니다.

## 4. 응답을 저장할 때

### 캐시를 둡니다

넥슨은 캐시를 "성능 최적화가 아니라 이 API를 쓰는 기본 전제"라고 안내합니다. 같은 캐릭터를 몇 분 안에 다시 물어보면 넥슨에 묻지 않고 저장해 둔 값을 돌려줍니다. 게임 데이터는 실시간이 아니어서(메이플스토리는 평균 15분 뒤 반영) 몇 분짜리 캐시로 잃는 것이 거의 없습니다.

**이 라이브러리에는 캐시가 없습니다.** 무엇을 얼마나 저장할지는 서비스마다 다르기 때문입니다. 아래는 캐릭터 기본 정보를 5분 동안 저장하는 가장 작은 예입니다. `card.mjs` 로 저장하고 `node --env-file=.env card.mjs` 로 실행합니다.

```js
import { createHash } from 'node:crypto';
import { NexonClient } from 'nexon-open-api';

const client = new NexonClient({ apiKey: process.env.NEXON_API_KEY ?? '' });

const cache = new Map();
const CACHE_MS = 5 * 60 * 1000;

// 저장소의 키에 고유 번호 원문을 넣지 않는다 (넥슨 안내). 해시로 바꿔서 쓴다
function cacheKey(kind, ocid) {
  return `${kind}:${createHash('sha256').update(ocid).digest('hex')}`;
}

async function getBasicCached(ocid) {
  const key = cacheKey('basic', ocid);
  const saved = cache.get(key);
  if (saved && Date.now() - saved.savedAt < CACHE_MS) return saved.value;

  const value = await client.maplestory.character.getBasic({ ocid });
  cache.set(key, { value, savedAt: Date.now() }); // 받은 시각을 함께 남긴다
  return value;
}

const ocid = await client.maplestory.getOcid('캐릭터명');
console.log((await getBasicCached(ocid)).character_level); // 넥슨에 조회한다
console.log((await getBasicCached(ocid)).character_level); // 저장해 둔 값을 쓴다
```

### 출처를 표기합니다

넥슨 데이터를 보여 주는 화면에는 아래 문구를 표기합니다. 사이트라면 화면 아래쪽에, 디스코드 봇이라면 답장의 꼬리말에 넣습니다.

```
Data based on NEXON Open API
```

### 30일 이내에 갱신합니다

넥슨 API로 모은 데이터를 저장해 둔다면 **30일 이내에 다시 받아 갱신할 의무**가 있습니다. 몇 분짜리 캐시와는 별개로, 데이터베이스나 파일에 오래 보관하는 데이터(랭킹 기록, 길드원 목록 등)에 해당합니다.

- 저장할 때 받은 시각을 함께 남깁니다.
- 30일이 지나기 전에 다시 조회해 덮어쓰거나, 오래된 데이터를 지웁니다.

## 5. 고유 번호를 밖으로 내보내지 않습니다

캐릭터 이름으로 받는 고유 번호(OCID, OUID, 길드의 `oguild_id`)는 **조회에만 쓰는 값이고 공개해도 되는 값이 아닙니다.** 넥슨의 안내에 따르면 고유 번호 안에 내 API 키와 같은 계정에 묶인 값이 들어 있는 경우가 있습니다.

| 하지 않습니다                                      | 대신 이렇게 합니다                                          |
| -------------------------------------------------- | ----------------------------------------------------------- |
| 주소(URL)에 고유 번호 넣기 (`/character/고유번호`) | 주소에는 캐릭터 이름을 쓰고, 고유 번호는 서버 안에서만 쓴다 |
| 웹페이지로 고유 번호 내려 주기                     | 웹페이지에 필요한 값(이름, 레벨 등)만 골라서 내려 준다      |
| 로그와 에러 메시지에 고유 번호 그대로 남기기       | 앞 8자만 남긴다                                             |
| 캐시·파일 이름에 고유 번호 넣기                    | 해시로 바꿔서 쓴다 ([위 예제](#캐시를-둡니다))              |
| 이슈나 질문 글에 실제 응답 그대로 붙이기           | API 키, 고유 번호, 실제 캐릭터 이름을 지우고 붙인다         |

고유 번호는 게임 콘텐츠 변경으로 바뀔 수 있다고 넥슨이 안내합니다. 오래 저장해 둔 번호로 조회가 안 되면 이름으로 다시 받습니다. 데이터베이스에 저장한다면 칸의 길이를 64자 이상으로 잡습니다.

**라이브러리가 하는 일** — `debug: true` 로 켜는 디버그 로그는 고유 번호를 가려서 출력합니다. 직접 남기는 로그에는 `maskIdentifier()`·`maskIdentifiers()` 를 쓸 수 있습니다. 주소, 웹페이지, 파일 이름에 고유 번호를 넣지 않는 일은 직접 챙겨야 합니다.

## 6. 화면 문구를 상황에 맞춥니다

넥슨이 돌려주는 에러 설명을 방문자에게 그대로 보여 주지 않습니다. 없는 캐릭터 이름을 조회해도 넥슨은 "파라미터 오류"라고 답하는데, 방문자는 이 말을 자기 오타가 아니라 서비스 고장으로 읽습니다.

| 상황                    | 에러 종류                | 화면 문구 예                                             |
| ----------------------- | ------------------------ | -------------------------------------------------------- |
| 없는 캐릭터, 오타       | `NexonNotFoundError`     | "캐릭터를 찾을 수 없어요. 이름을 다시 확인해 주세요."    |
| 이름을 안 넣음          | `NexonBadRequestError`   | "캐릭터 이름을 입력해 주세요."                           |
| 그날 데이터가 아직 없음 | `NexonDataNotReadyError` | "아직 데이터가 준비되지 않았어요."                       |
| 게임 점검               | `NexonMaintenanceError`  | "지금은 게임 점검 중이에요."                             |
| 조회가 몰림             | `NexonRateLimitError`    | "지금 조회가 몰리고 있어요. 조금 뒤 다시 시도해 주세요." |
| 키 문제, 넥슨 서버 오류 | 그 밖의 `NexonError`     | "조회 중 문제가 생겼어요." (자세한 내용은 운영자 로그로) |

- 고유 번호를 받았다고 바로 "찾았습니다"라고 표시하지 않습니다. 고유 번호는 나오는데 정보 조회에서 실패하는 캐릭터가 있습니다. 정보 조회까지 끝난 뒤에 표시합니다.
- 기록이 없는 항목은 `null` 이 아니라 `0` 이나 빈 목록으로 오기도 합니다. 화면에는 "기록 없음"으로 맞춰 보여 줍니다.
- 랭킹을 모아 "직업별 인구" 같은 집계를 만들었다면, 전체 유저가 아니라 랭킹 상위 몇 명을 센 것인지 화면에 함께 적습니다.

상황마다 다른 답을 하는 완성 예제는 [`examples/error-handling.mjs`](../examples/error-handling.mjs)에 있습니다.
