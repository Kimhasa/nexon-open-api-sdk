## 1. API Key는 서버에만 둡니다

- **API Key는 서버 또는 봇의 Node.js 환경에서 관리합니다.** 브라우저에서 실행하는 코드에 API Key를 넣으면 방문자가 개발자 도구에서 확인할 수 있으며, 노출된 API Key로 호출 허용량에 도달할 수 있습니다. 웹사이트에서는 **브라우저 → 서비스 서버 → NEXON Open API** 순서로 요청합니다. [FAQ의 서버 예제](faq.md#웹페이지에서-바로-부르고-싶어요)를 참고해 주세요.
- **API Key는 `.env` 파일에서 관리합니다.** 코드에서 `process.env`로 읽습니다 ([시작 가이드](getting-started.md#3-env-파일로-api-key-관리하기)).
- **`.env`를 GitHub에 올리지 않습니다.** `.gitignore` 파일에 `.env` 한 줄을 추가합니다. API Key가 노출됐다면 NEXON Open API의 애플리케이션 상세 페이지에서 새 API Key를 발급받아 교체해 주세요.
- **API Key는 게임별로 발급됩니다.** 여러 게임을 다루면 `NEXON_MAPLESTORY_API_KEY`, `NEXON_FC_ONLINE_API_KEY`처럼 이름을 나눠 저장하고, 게임마다 `NexonClient`를 따로 만듭니다 ([FAQ](faq.md#api-key가-잘못됐다고-나와요)).

**라이브러리의 적용 범위** — API Key가 비어 있으면 `new NexonClient()`에서 에러를 발생시킵니다. 다른 게임의 API Key를 사용하면 에러 메시지에 필요한 게임을 표시합니다. API Key의 보관 위치는 서비스에서 관리합니다.

## 2. 서비스 단계 애플리케이션을 등록합니다

NEXON Open API의 호출 허용량은 애플리케이션 타입에 따라 다릅니다.

| 애플리케이션 타입 | 초당 최대 허용량 | 1일 최대 허용량 |
| ----------------- | ---------------- | --------------- |
| 개발 단계         | 5건              | 1,000건         |
| 서비스 단계       | 500건            | 20,000,000건    |

- 넥슨은 개발 단계에서 테스트한 뒤, 서비스 주소(URL)가 준비되면 **서비스 단계 애플리케이션을 새로 등록**하도록 안내합니다.
- **서비스 단계로 전환할 때는 API Key를 새로 발급받습니다.** 개발 단계에서 발급받은 API Key는 자동으로 전환되지 않으므로 서버의 `.env`를 새 API Key로 갱신합니다.
- 호출량은 애플리케이션별로 합산됩니다. API Key는 게임별로 발급되므로 게임마다 호출 허용량을 확인합니다.

이 라이브러리의 실서버 검증에서도 개발 단계의 1일 호출 허용량인 1,000건에 도달했습니다.

## 3. 호출량을 확인합니다

화면을 구성하는 데 필요한 호출량을 확인합니다. 아래 표는 넥슨이 가이드에서 예시로 안내한 프로필 카드 한 장의 호출량입니다.

| 단계                 | 호출량 |
| -------------------- | ------ |
| 이름 → 식별자(ocid)  | 1      |
| 기본 정보            | 1      |
| 능력치·상세 정보     | 6      |
| **합계**             | **8**  |
| 순위 배지까지 넣으면 | 13~15  |

- 랭킹은 한 번에 한 종류의 순위만 돌려주기 때문에, 순위를 넣으면 호출이 거의 두 배가 됩니다.
- 개발 단계의 호출 허용량은 1초에 5건이라 카드 한 장(8회)도 한꺼번에 부를 수 없습니다. 하루 1,000건으로는 카드 약 125장입니다.
- 길드원 100명을 `Promise.all`로 동시에 조회하면 초당 호출 허용량을 바로 넘습니다. 몇 명씩 나눠 순서대로 조회합니다.
- 한 캐릭터의 순위는 랭킹 페이지를 넘기며 찾지 않습니다. 메이플스토리 랭킹은 `ocid`를 넣으면 그 캐릭터의 순위만 돌려줍니다 ([메이플스토리 문서](maplestory.md)).

**라이브러리의 적용 범위** — 빈 이름 등 유효하지 않은 값은 요청 전에 검사합니다. HTTP 429 응답을 받으면 간격을 늘려 자동으로 재시도합니다. 화면별 호출량과 동시 요청 수는 서비스에서 정합니다.

## 4. 응답을 저장할 때

### 캐시를 둡니다

넥슨은 캐시를 "성능 최적화가 아니라 이 API를 쓰는 기본 전제"라고 안내합니다. 같은 캐릭터를 몇 분 안에 다시 물어보면 넥슨에 묻지 않고 저장해 둔 값을 돌려줍니다. 게임 데이터는 실시간이 아니어서(메이플스토리는 평균 15분 뒤 반영) 몇 분짜리 캐시로 잃는 것이 거의 없습니다.

**이 라이브러리에는 캐시가 없습니다.** 무엇을 얼마나 저장할지는 서비스마다 다르기 때문입니다. 아래는 캐릭터 기본 정보를 5분 동안 저장하는 가장 작은 예입니다. `card.mjs`로 저장하고 `node --env-file=.env card.mjs`로 실행합니다.

```js
import { createHash } from 'node:crypto';
import { NexonClient } from 'nexon-open-api';

const client = new NexonClient({ apiKey: process.env.NEXON_API_KEY ?? '' });

const cache = new Map();
const CACHE_MS = 5 * 60 * 1000;

// 저장소의 키에 식별자 원문을 넣지 않는다 (넥슨 안내). 해시로 바꿔서 쓴다
function cacheKey(kind, ocid) {
  return `${kind}:${createHash('sha256').update(ocid).digest('hex')}`;
}

async function getBasicCached(ocid) {
  const key = cacheKey('basic', ocid);
  const saved = cache.get(key);
  if (saved && Date.now() - saved.savedAt < CACHE_MS) return saved.value;

  const value = await client.maplestory.character.getBasic({ ocid });
  cache.set(key, { value, savedAt: Date.now() }); // 받은 시각을 함께 남긴다
  return value;
}

const ocid = await client.maplestory.getOcid('캐릭터명');
console.log((await getBasicCached(ocid)).character_level); // 넥슨에 조회한다
console.log((await getBasicCached(ocid)).character_level); // 저장해 둔 값을 쓴다
```

### 출처를 표기합니다

NEXON Open API 데이터를 표시하는 화면에는 다음 출처 문구를 표시해 주세요. 사이트의 화면 하단이나 디스코드 봇 응답의 하단에 표시할 수 있습니다.

```
Data based on NEXON Open API
```

### 30일 이내에 갱신합니다

NEXON Open API로 모은 데이터를 저장해 둔다면 **30일 이내에 다시 받아 갱신할 의무**가 있습니다. 몇 분짜리 캐시와는 별개로, 데이터베이스나 파일에 오래 보관하는 데이터(랭킹 기록, 길드원 목록 등)에 해당합니다.

- 저장할 때 받은 시각을 함께 남깁니다.
- 30일이 지나기 전에 다시 조회해 덮어쓰거나, 오래된 데이터를 지웁니다.

## 5. 식별자를 외부에 공개하지 않습니다

**캐릭터 식별자(ocid), 계정 식별자(ouid), 길드 식별자(oguild_id)는 조회에만 사용합니다.** 넥슨은 식별자에 API Key와 같은 계정에 연결된 값이 포함될 수 있다고 안내합니다.

| 하지 않습니다                                   | 대신 이렇게 합니다                                                     |
| ----------------------------------------------- | ---------------------------------------------------------------------- |
| 주소(URL)에 식별자 넣기 (`/character/고유번호`) | 주소에는 캐릭터 이름을 쓰고, 식별자는 서버에서만 사용합니다.           |
| 웹페이지로 식별자 내려 주기                     | 웹페이지에는 이름, 레벨 등 필요한 값만 전달합니다.                     |
| 로그와 에러 메시지에 식별자 그대로 남기기       | 앞 8자만 남깁니다.                                                     |
| 캐시·파일 이름에 식별자 넣기                    | 해시로 변환해 사용합니다. [캐시 예제](#캐시를-둡니다)를 참고해 주세요. |
| 이슈나 질문 글에 실제 응답 그대로 붙이기        | API Key, 식별자, 실제 캐릭터 이름을 제외합니다.                        |

식별자는 게임 콘텐츠 변경으로 바뀔 수 있다고 넥슨이 안내합니다. 오래 저장해 둔 식별자로 조회가 안 되면 이름으로 다시 받습니다. 데이터베이스에 저장한다면 칸의 길이를 64자 이상으로 잡습니다.

**라이브러리의 적용 범위** — `debug: true`로 설정하면 디버그 로그의 요청 URL과 응답 검증 로그의 URL에서 식별자를 가립니다. 서비스에서 남기는 로그에는 `maskIdentifier()`와 `maskIdentifiers()`를 사용할 수 있습니다. 주소, 웹페이지, 파일 이름에서 식별자를 보호하는 일은 서비스에서 구현합니다.

## 6. 화면 문구를 상황에 맞춥니다

NEXON Open API의 에러는 상황에 맞는 문구로 안내합니다. 예를 들어 없는 캐릭터 이름을 조회할 때 반환되는 "파라미터 오류"는 방문자가 서비스 오류로 이해할 수 있으므로 캐릭터 이름을 확인하도록 안내합니다.

| 상황                                   | 에러 종류                | 화면 문구 예                                             |
| -------------------------------------- | ------------------------ | -------------------------------------------------------- |
| 없는 캐릭터, 오타                      | `NexonNotFoundError`     | "캐릭터를 찾을 수 없어요. 이름을 다시 확인해 주세요."    |
| 이름을 안 넣음                         | `NexonBadRequestError`   | "캐릭터 이름을 입력해 주세요."                           |
| 그날 데이터가 아직 없음                | `NexonDataNotReadyError` | "아직 데이터가 준비되지 않았어요."                       |
| 게임 점검                              | `NexonMaintenanceError`  | "지금은 게임 점검 중이에요."                             |
| 조회가 몰림                            | `NexonRateLimitError`    | "지금 조회가 몰리고 있어요. 조금 뒤 다시 시도해 주세요." |
| API Key 오류, NEXON Open API 서버 오류 | 그 밖의 `NexonError`     | "조회 중 문제가 생겼어요." (자세한 내용은 운영자 로그로) |

- 식별자를 받았다고 바로 "찾았습니다"라고 표시하지 않습니다. 식별자는 나오는데 정보 조회에서 실패하는 캐릭터가 있습니다. 정보 조회까지 끝난 뒤에 표시합니다.
- 기록이 없는 항목은 `null`이 아니라 `0` 이나 빈 목록으로 오기도 합니다. 화면에는 "기록 없음"으로 맞춰 보여 줍니다.
- 랭킹을 모아 "직업별 인구" 같은 집계를 만들었다면, 전체 유저가 아니라 랭킹 상위 몇 명을 센 것인지 화면에 함께 적습니다.

상황마다 다른 답을 하는 완성 예제는 [`examples/error-handling.mjs`](../examples/error-handling.mjs)에 있습니다.
