# AI 코딩 도구와 함께 쓰기

Claude, ChatGPT, Cursor, GitHub Copilot 같은 AI 도구로 봇이나 사이트를 만들 때 `nexon-open-api` 를 함께 쓰는 법입니다.

## 왜 AI에게 이 라이브러리를 쓰라고 하나요

AI는 넥슨 포털의 API 문서(OpenAPI 스펙)를 보고 코드를 짭니다. 그런데 이 스펙은 실제 응답과 다른 곳이 많습니다. 2026-11-24 게임별 실제 키로 263개 API를 공개 캐릭터 42명으로 대조했더니 600곳이 넘게 달랐습니다. 아래는 그중 몇 가지이고, 스펙만 보고 짠 코드는 이런 곳에서 조용히 틀립니다.

| 스펙만 보고 짠 코드                                               | 실제로 일어나는 일                                                             |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 장비의 업그레이드 가능 횟수를 `scroll_upgradable_count` 로 읽는다 | 실제 필드는 `scroll_upgradeable_count` 라서 항상 `undefined` 가 된다           |
| 없는 캐릭터면 "찾을 수 없음" 에러가 올 거라 생각한다              | 넥슨은 "파라미터 오류"(`OPENAPI00004`)를 준다. 봇이 "잘못된 요청"이라고 답한다 |
| 영웅전 랭킹을 배열로 받는다                                       | 실제로는 `{ ranking: [...] }` 라서 `list[0]` 이 비어 있다                      |
| 펫 장비 이름을 바로 읽는다                                        | 장착하지 않은 칸은 `null` 이라 화면이 멈춘다                                   |

넥슨도 같은 문제를 알고 있어서 [AI 에이전트 가이드](https://openapi.nexon.com/ko/guide/ai-agent/)를 따로 두고 "스펙을 그대로 믿지 말고 엔드포인트마다 실제 응답과 대조하라"고 안내합니다. 이 라이브러리는 그 대조를 이미 해 두었습니다. AI에게 이 라이브러리를 쓰라고 하면 검증된 메서드·필드 이름과 에러 처리를 그대로 가져다 씁니다. 더 자세한 비교는 [왜 이 라이브러리인가](./why.md)에 있습니다.

## 1. AI가 읽을 안내 파일

| 파일            | 내용                                                                      | 어디서                                                                                                                                      |
| --------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `llms.txt`      | 짧은 소개와 문서 목록                                                     | [GitHub](https://github.com/Kimhasa/nexon-open-api-sdk/blob/main/llms.txt)                                                                  |
| `llms-full.txt` | 코드 생성 규칙 + 15개 게임의 공개 메서드 전체 (시그니처와 게임 용어 설명) | 설치 후 `node_modules/nexon-open-api/llms-full.txt`, 또는 `https://raw.githubusercontent.com/Kimhasa/nexon-open-api-sdk/main/llms-full.txt` |

`llms-full.txt` 는 SDK 소스에서 자동으로 만들어지므로 설치한 버전의 메서드 이름과 항상 일치합니다.

## 2. 프로젝트에 지침 한 번 넣어 두기

AI 도구는 프로젝트의 지침 파일을 매번 읽습니다. 아래 내용을 붙여 넣어 두면 요청할 때마다 설명하지 않아도 됩니다.

| 도구           | 붙여 넣을 곳                      |
| -------------- | --------------------------------- |
| Claude Code    | 프로젝트 폴더의 `CLAUDE.md`       |
| Cursor         | `.cursor/rules/nexon.md`          |
| GitHub Copilot | `.github/copilot-instructions.md` |
| 그 밖의 도구   | 대화 맨 처음에 붙여 넣기          |

```markdown
## 넥슨 게임 데이터

- 넥슨 게임 데이터는 `nexon-open-api` 패키지로 가져온다. `open.api.nexon.com` 을 직접 fetch하지 않는다.
- 사용법과 메서드 목록은 `node_modules/nexon-open-api/llms-full.txt` 를 먼저 읽는다. 필드 이름은 추측하지 말고 타입을 따른다.
- API 키는 게임마다 따로다. `.env` 의 `NEXON_<게임>_API_KEY` 를 서버에서만 읽는다.
- 조회는 이름 → 고유 번호(OCID·OUID) → 정보 순서다. 고유 번호는 화면·URL·로그에 원문으로 남기지 않는다.
- 최신 데이터는 date를 생략한다. 오늘·미래 날짜를 넣지 않는다.
- 에러는 instanceof 로 나눈다: 없는 캐릭터 NexonNotFoundError, 점검 NexonMaintenanceError, 키 문제 NexonAuthError, 호출 한도 NexonRateLimitError.
- 결과를 캐시하고, 화면에 "Data based on NEXON Open API" 를 표기한다.
```

## 3. 이렇게 요청하세요

만들고 싶은 것을 게임 용어로 말하고, 라이브러리와 안내 파일을 같이 알려 줍니다.

**디스코드 봇**

> nexon-open-api 패키지로 디스코드 봇의 `!정보 캐릭터명` 명령에 답하는 함수를 만들어 줘. 메이플스토리 캐릭터의 레벨, 직업, 월드, 길드, 전투력, 유니온 레벨을 한 메시지로 보여 주고, 없는 캐릭터·점검 중·호출 한도일 때는 다른 문구를 보여 줘. 사용법은 node_modules/nexon-open-api/llms-full.txt 를 따라.

**랭킹 페이지**

> nexon-open-api 로 메이플스토리 어제 기준 종합 랭킹 TOP 10을 표로 출력해 줘. 월드는 스카니아로 거르고, 한 번 받은 결과는 1시간 캐시해 줘.

**장비 분석 도구 (환산 계산기 재료)**

> nexon-open-api 로 캐릭터의 장착 장비를 받아서 스타포스, 잠재능력, 에디셔널 잠재능력, 추가옵션을 장비별로 정리하고 주스탯 % 합계를 계산해 줘. 옵션 문자열은 "STR +12%" 형식이야.

**경매장 시세**

> nexon-open-api 로 마비노기 경매장에서 아이템 이름으로 매물을 최대 3페이지까지 모아 개당 최저가와 평균가를 알려 줘. 다음 페이지는 next_cursor 로 넘겨.

## 4. AI가 짠 코드 점검표

AI가 만든 코드를 실행하기 전에 아래를 확인하세요. 하나라도 어긋나면 고쳐 달라고 다시 요청합니다.

- [ ] `open.api.nexon.com` 을 직접 `fetch` 하지 않고 `nexon-open-api` 를 쓴다
- [ ] API 키를 코드에 적지 않고 `.env` 에서 읽는다. 웹페이지(브라우저) 코드에 키가 없다
- [ ] 여러 게임을 다루면 게임마다 키와 `NexonClient` 를 따로 만든다
- [ ] 최신 데이터에 `date` 를 넣지 않았다. 오늘 날짜를 넣지 않았다
- [ ] 없는 캐릭터(`NexonNotFoundError`), 점검(`NexonMaintenanceError`), 호출 한도(`NexonRateLimitError`)를 나눠 안내한다
- [ ] `| null` 인 필드를 확인하고 쓴다
- [ ] 고유 번호(OCID·OUID)를 화면·URL·로그에 원문으로 남기지 않는다
- [ ] 같은 조회를 반복하지 않도록 캐시한다. 개발 단계 키는 하루 1,000건까지다
- [ ] 화면에 "Data based on NEXON Open API" 를 표기한다

## 5. 넥슨 공식 AI 에이전트 가이드와의 관계

넥슨의 [AI 에이전트 가이드](https://openapi.nexon.com/ko/guide/ai-agent/)는 원 API를 직접 부를 때 어긋나는 지점을 정리한 문서입니다. 이 라이브러리를 쓰면 그 지점 대부분을 SDK가 처리합니다. 어떤 항목을 SDK가 처리하고 어떤 항목이 여러분 몫인지는 [왜 이 라이브러리인가](./why.md)의 대응표에 있습니다. 서비스로 공개하기 전에는 [서비스에 올리기 전 체크리스트](./service-checklist.md)도 확인하세요.
